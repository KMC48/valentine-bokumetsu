# アワード応募前の不具合修正（v0.2.5、2026-11-14）

やまなしメディア芸術アワード2026-27（締切 2026-11-19 17:00）への応募前に、公開版 v0.2.4 を通しで遊んで見つけた3点を直した。

## 直したこと

| 不具合 | 原因 | 修正 |
| --- | --- | --- |
| ストーリーを曲の読み込み前にスキップすると、探索中もストーリーの曲が鳴り続ける | 読み込みが終わった曲を、今の画面と照合せずに鳴らしていた | 最後に要求された曲だけを鳴らす（`app/src/game/audioEngine.ts`） |
| Sランクに誰も届かない | Sの基準 5,000点が、理論上の最高点 4,870点より高かった | Sの基準を 4,200点に変更（`app/src/data/score.ts`） |
| 全員を通報して撲滅率100%でも「女子生徒たちの完全勝利」の結末が出る | 結末を得点だけで選んでいた | 撲滅率100%のB・Cランクは、誤認通報に触れる結末にする（`app/src/game/ending.ts`） |

### Sの基準を 4,200点にした理由

1校あたりのチョコは10件。全部押さえて誤認ゼロのときの得点は、通報の順番しだいで 4,220〜4,870点になる。
4,200点なら「全部押さえて誤認ゼロなら必ずS」になる。A（3,500点）・B・C・Dの基準は変えていない。

### 撲滅率100%のときの結末

- **Cランク（誤認3件以上）**：Dランクと同じ「誤認通報が多すぎる」の話を、ランク表示は C のまま出す。絵は無い（Dランクの結末にはもともと絵が無い）。
- **Bランク**：冒頭3行を「すべて押収された／誤認通報が◯件残った／胸を張れないか」に差し替える。絵と題名はBのまま。
- 取り逃がしがあるときの結末は変えていない。

差し替えた3行の文面は仮のもの。言い回しはオーナーの判断で直してよい。

## 検証

- `npx tsc --noEmit`：成功。
- `npx vitest run`：17ファイル・148件成功（今回追加した10件を含む）。追加したBGMのテスト3件は、修正前のコードでは3件とも失敗することを確認した。
- `npm run build`：成功。
- `npm run verify:web`：3件中1件が失敗。プライバシーポリシーの改行コード（Windowsで CRLF になる）が原因で、今回の変更とは無関係。同じテストは GitHub 上（Linux）の main では成功している。
- ブラウザ（Chromium系、ビルドした配布物）で確認：
  - 曲の読み込みを1.2秒遅らせてすぐスキップしても、探索ではポップの曲のまま（修正前はストーリーの曲に変わった）。
  - 1周目を全部押さえて誤認ゼロで 4,870点・Sランク・「バレンタイン完全撲滅」の結末と絵が出る。
  - 1周目で全員を通報すると 1,920点・Cランク・撲滅率100%で、「誤認通報が多すぎる」の結末が出る。
- 未確認：音を耳で聞いた確認、Safari、Mac、スマホ実機、2・3周目での同じ確認（データ上の得点構成は3校とも同じで、テストは3校とも通している）。

## 直していないこと（見つけたが今回の対象外）

- PCの大きい画面で上部の文字が小さい（1920×1080で 9.6〜11.5px）。
- セリフ欄に常にスクロールバーが出る（標準の文章が2pxはみ出す）。
- 画像の先読みが無く、初回は立ち絵が1秒弱遅れて出る。
- Dランクの結末に絵が無い。
- 遊び方の箇条書きの「・」が文章から離れている。タブのアイコンが無い。
