### 0914追加分の加工

原稿はグリーンバック／マゼンタバックで納品された（市松模様ではない）。
`../../scripts/build_0914_assets.py` が一括処理する。

```powershell
python scripts/build_0914_assets.py
```

- クロマキーは色相（HSV）で許容値を持たせて判定する。厳密な #00FF00 ではないため。
- 人物は「外周からつながる背景」だけを抜く（服の中の同系色を守る）。
- 白い線画アイコンは閉じた内側も抜く（家の中など）。`line_art=True` で切り替える。
- シートは均等割りではなく、アルファの空白列で分割する（鞄や髪の食い込み対策）。

## 人物の加工パイプライン

`画像素材/` の原稿は「市松模様が画像そのものに焼き込まれたRGB画像」（本物の透過ではない）。
`../../scripts/build_character_variants.py` が、原稿から以下2種類を生成する。

```powershell
python scripts/build_character_variants.py
```

| 出力 | 用途 | 加工内容 |
| --- | --- | --- |
| `xxx.png` | ステージ上の立ち絵 | 透過 → **実体ぴったりにトリミング** |
| `bust_xxx.png` | ストーリー画面（ノベルゲーム風） | 透過 → 頭の中心で **胸から上を切り出し** |

### 透過処理（`remove_checker_bg.py`）

1. 明るいグレースケール系ピクセルを背景候補にする。
2. 画像外周から4連結でつながる領域を背景と判定（人物内部の白いシャツを誤って消さないため）。
3. 外周とつながっていない“閉じた”隙間（上げた腕と頭の間、脚の間、後れ毛の裏など）は、
   **市松模様かどうか**で判定する。判定は「明暗2トーンが混在」かつ
   「明タイルの塊が6個以上＝格子状」の両方を満たすこと。
   - この2段階にしないと、白い腕章や紙のような単色の閉領域まで透明化してしまう（実際に発生した）。
4. フェザリングで縁をアンチエイリアス。

品質確認：全キャラを明背景・暗背景・赤背景に合成し、
「市松模様の抜け残り」と「抜けすぎ（腕章・シャツの穴あき）」の両方が無いことを目視確認済み。

### トリミングが必要な理由

原稿は左右の余白が不均等（例：girl_001 は実体が画像の左7%〜右70%、girl_003 は35%〜75%）。
これをそのまま `left: 50%` で配置すると、キャラごとに横位置がずれる。
実体ぴったりに切ると「箱の底＝足元」「箱の横中央＝キャラの中心」になり、配置が素直に効く。

## パスの指定元

コードから直接パス文字列を書かず、`src/data/assets.ts` の `ASSETS` を経由すること。
`status` が `"ready"` 以外の場合は呼び出し側で仮表示（SVG/CSS）にフォールバックする設計。

## 生徒の立ち位置について

ステージ上の配置は `src/data/students.ts` の `position` と、
`src/data/areas.ts` の `floor`（床の台形）で決まる。

- `position.y` … 足元の高さ（ゲームエリアの上から%）。奥ほど小さい値。
- `position.x` … **床の左端0〜右端100** の相対値。画面のX座標ではない。
  廊下は奥ほど床が狭いので、`floorX()` が奥行きに応じて実際のX座標へ変換する
  （この変換が無いと、奥の生徒が壁やロッカーの上に立って見える）。
- 大きさは `StudentTarget.tsx` の `DEPTH` が `position.y` から**高さ**を決める。
  幅ではなく高さ基準なのは、鞄を持つ子など横幅の比率がキャラごとに違うため。
- 背景の見せ方は `areas.ts` の `focusY`（object-position の縦位置）で調整する。
  大きくするほど床側が映る。
