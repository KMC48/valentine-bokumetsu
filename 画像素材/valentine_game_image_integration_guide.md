# バレンタイン撲滅委員会：画像素材組み込み指示書

対象：React / TypeScript / Viteによるスマートフォン縦画面向けMVP  
作成日：2026-09-13  
併読資料：`valentine_annihilation_game_MVP_spec(1).md`  
目的：生成済み画像を、どの画面のどのレイヤーに、どう配置するかを定義する。

> 本書は画像組み込み用の追加指示書。ゲームルール・得点・分岐条件は元のMVP仕様書を優先する。本書の配置数値は実装開始用の提案値であり、実機表示で調整する。
> 本書だけに画像データは含まれない。後述の元画像21点も実装環境へ渡すこと。本書作成時点で画像の改名・配置・透過修正・WebP変換は行っていない。

## 1. 最初に守ること

1. 完成画面の参考画像をゲーム画面の背景として使用しない。背景、人物、HUD、照準、ボタン、セリフを分離する。
2. タイトル背景・エンディングCGには人物が描かれている。その上に同じ人物の立ち絵を追加しない。
3. 通常ステージは人物のいない背景に、独立した生徒ターゲットを配置する。
4. スコア・タイマー・ミッション・セリフ・ランクはHTMLの文字として描画する。画像への焼き込みは禁止。
5. 画像の外見だけで`chocolateType`を決定しない。判定はゲームデータが唯一の正とする。ただし、画像とヒントが明白に矛盾するデータは作らない。
6. 元画像は保持する。実装用画像はコピーまたは加工済みの別ファイルとして作る。
7. ファイルがない、透過できないという理由でゲームの進行実装を止めない。未完成素材には仮表示を用意する。

## 5. 周回×時間帯の背景設定

現在は周回別に朝・昼・放課後の3枚ずつ、合計9枚が揃っているわけではない。以下をMVPでの暫定割り当てとする。

| 周回 | 朝 | 昼 | 放課後 | 補足 |
|---|---|---|---|---|
| 1：公立校 | BG01 | BG02 | BG03 | 時間帯・場所とも素材が対応 |
| 2：私立進学校 | BG04 | BG04 | BG04 | 時間はHUD・シナリオで明示。昼光の廊下を共用する暫定版 |
| 3：エリート校 | BG05 | BG05 | BG05 | 同上。学校の外観差を優先 |

2・3周目の放課後には薄い暖色オーバーレイを加えてもよいが、実際の夕景素材があるとは扱わない。濃いフィルターで観察に必要な色を変えない。

BG06は共通屋上としてイベントで再利用できる。学校固有の屋上が完成するまでは、学校名の看板などを新たに焼き込まない。

周回ごとの隠し方・フェイク率・ヒント数は既存の`loops.ts`などで管理する。背景を差し替えただけで難易度差を実装済みとしない。

## 6. ステージ内の配置

### 6.1 表示領域

- 基準は9:16、最大幅540px。基本レイアウトはスマホ縦画面。
- 背景は画面全体を覆う`object-fit: cover`。縦横別々に引き伸ばさない。
- HUD領域の目安：画面上端〜22%。
- 探索領域の目安：上から24〜80%。ここを独立した`position: relative`コンテナにする。
- 下部UI領域の目安：80〜100%。通報・会話欄が生徒の顔や所持品を隠さないようにする。
- 縦方向が収まらない小画面ではUI寸法を調整し、必要な操作を画面外へ追い出さない。セーフエリアも確保する。

以下の座標は**探索領域内**の足元位置。画面全体の座標と混同しない。

| スロット | x (%) | 足元y (%) | 画像の高さ：探索領域比 | 主な位置 |
|---|---:|---:|---:|---|
| A | 20 | 58 | 40% | 左奥 |
| B | 49 | 54 | 40% | 中央奥 |
| C | 79 | 61 | 43% | 右奥 |
| D | 31 | 96 | 59% | 左手前 |
| E | 69 | 97 | 60% | 右手前 |

5人を同じ大きさで横並びにしない。奥の人物を小さく、手前の人物を大きくする。背景ごとに机や壁の上に立っていないか調整する。特に教室BG02は左側に机があるため、足元を通路側へ寄せる。

### 6.2 レイヤー順

| z-index目安 | レイヤー | 入力 |
|---:|---|---|
| 0 | 背景 | `pointer-events: none` |
| 1 | 時間帯・暗転オーバーレイ | `pointer-events: none` |
| 10〜99 | 生徒・教師。足元が下ほど手前 | 生徒ボタンのみ有効 |
| 110 | 選択照準・ヒントマーカー | `pointer-events: none` |
| 200 | HUD・通報ボタン・会話欄 | 操作要素のみ有効 |
| 300 | モーダル背面 | 背後へのタップを遮断 |
| 310 | 観察・通報結果モーダル | フォーカスをモーダル内に限定 |

人物は縦横比を保ち`object-fit: contain`。足元アンカーに`translate(-50%, -100%)`を使う場合、パーセントの高さは固定寸法を持つ探索コンテナを基準にする。透明な余白が大きい元画像では足元にずれが出るため、トリミング済み画像か個別のアンカー補正を使う。

### 6.3 タップと主人公表示

- 生徒全身を囲む過大な四角い当たり判定を作らない。透明余白を除いた範囲にボタンを合わせる。
- 近くの生徒が重なった場合は配置を調整し、全員を選択可能にする。
- 小さなターゲットにも44px程度以上の操作領域を確保する。
- 主人公の全身を常時手前に置くと観察を妨げるため、通常ステージでは会話欄の顔アイコンとして表示する。
- 顔アイコンは背景除去済みPLAYERを切り出すか、CSSの表示枠で顔を見せる。必要なら別途ポートレート素材を作る。
- 素材の左右反転は腕章・所持品の左右も変わるため、原則行わない。

## 7. ストーリー・観察・通報の見せ方

### 7.1 ストーリー

1人表示なら中央〜やや右、2人なら左右に分ける。人物の高さは画面の65〜72%を目安とし、下部20〜25%に会話欄を重ねる。表情差分は現在未生成。通常立ち絵を使い、セリフや軽い拡大で補う。表情差分ファイルが存在すると仮定した参照を書かない。

### 7.2 観察モーダル

上側に選択人物の胸上〜所持品が見える範囲、下側に名前・仕草・所持品・会話を表示する。小画面では内容部分をスクロール可能にする。対象画像はターゲットと同じものを使う。

観察時に「友チョコ」「本命」と分類名を表示しない。例：紙袋の画像なら「ハート柄の紙袋」、閉じた鞄なら「中身は見えない」。推理前に`chocolate_honmei.png`を出すと正解の漏洩になるため禁止。

### 7.3 通報結果

| 判定 | 小物 | 演出 | 得点の初期値 |
|---|---|---|---:|
| friend | `chocolate_friend.png` | 小さな赤いフラッシュ＋発見表示 | +100 |
| honmei | `chocolate_honmei.png` | 赤・金の強調＋摘発表示 | +500 |
| honmei_special | `chocolate_special.png` | 大きな強調＋告白直前阻止表示 | +1000 |
| none | その生徒の実際の無実の所持品、または小物なし | 青灰色＋誤認表示 | -300 |

得点は定数から取得し、表の値をUI内へ重複して直書きしない。コンボを適用した実際の加算値を表示する。教師画像の表示は演出であり、その読み込み成功を判定処理の条件にしない。

## 8. 女子5人を使うMVPの15ターゲット例

以下は1周目の仮配置例。キャラクターの絵柄は5種類であり、15種類の別人の立ち絵が生成済みという意味ではない。同じ女子が各時間帯に登場する設計にし、`characterId`とステージ固有の`targetId`を分ける。

| 各時間帯の人物 | 朝 | 昼 | 放課後 | 画像との整合 |
|---|---|---|---|---|
| GIRL01 | friend | friend | friend | 袋の中身は会話・判定で明かす |
| GIRL02 | friend | friend | friend | 小分けチョコを持つ外見と一致 |
| GIRL03 | honmei | honmei | honmei | 特別な箱を隠している |
| GIRL04 | none | none | none | 教科書と弁当。チョコと断言しない |
| GIRL05 | none | none | honmei_special | 放課後に新たな品を預かったなど、所持状態が変わる理由を脚本へ入れる |

合計：無実5、友チョコ6、本命3、特殊本命1。元仕様書の仮内訳に対応する。

同じ人物の所持品を前ステージで確認・回収した設定なら、次の時間帯で再び所持している理由をシナリオで補う。ステージをまたいだ同一ターゲットの二重加点ではなく、別イベントとして扱う。

## 9. 結果画面とエンディング分岐

最終結果画面はスコア集計の表示、エンディング画面は結末CGの表示、と役割を分ける。

通常の割り当て：S→END_S、A→END_A、B→END_B、CまたはD→END_C。

特殊エンディングの条件は元仕様では例示段階であり未確定。既存実装の条件があればそれを優先する。未実装なら条件を設定化し、暫定無効にして通常分岐を動かす。本書だけを根拠に勝手な条件を確定しない。

特殊条件が確定して有効になった場合の推奨優先順位は「特殊→通常ランク」。設定で一意に1枚を選び、通常と特殊のCGが連続で誤表示されないようにする。

CGは`object-fit: cover; object-position: center`を初期値とする。特殊エンドは顔とチョコを渡す手が重要なので、切れそうな画面では`contain`＋周囲の紺背景へ切り替える。下部の会話欄が重要な手元を隠す場合は高さを縮める。

学校別のエンディングCGは未生成。MVPでは同じ5枚を共用する。特定校の建築が一致しない点は後から専用CGに差し替える対象とする。

## 11. パスとデータの管理

`public/assets/...`の画像をブラウザから参照するURLは`/assets/...`。`/public/assets/...`と書かない。サブパス配信を使うプロジェクトでは既存のベースURL処理へ合わせる。

画像管理は既存構成に合わせて`src/data/assets.ts`等へ集約する。次は構造例であり、そのまま既存コードを置き換える指示ではない。

```ts
type AssetStatus = 'ready' | 'needs-alpha' | 'needs-review' | 'missing';
type GameAsset = {
  src: string;
  status: AssetStatus;
  kind: 'background' | 'character' | 'ending' | 'item';
};

export const assets: Record<string, GameAsset> = {
  morning: {
    src: '/assets/backgrounds/school_morning.png',
    status: 'ready', kind: 'background',
  },
  player: {
    src: '/assets/characters/player.png',
    status: 'needs-alpha', kind: 'character',
  },
  endingS: {
    src: '/assets/endings/ending_s.png',
    status: 'ready', kind: 'ending',
  },
};
```

この例の`ready`は、対応するファイルを配置した後に有効。`status !== 'ready'`なら仮表示を返す。透過修正試行版を採用する場合も目視確認後に変更する。

生徒データは`characterId`、背景データは`backgroundId`、結末データは`endingAssetId`などで参照する。型定義は既存プロジェクトへ合わせる。コンポーネント各所へランダムな`exec-....png`名を直書きしない。

## 12. 読み込みとエラー対策

- タイトル表示時はTITLE01を優先。全CGを最初に一括読み込みしない。
- ステージ開始前に、その背景と表示する人物だけを先読みする。
- 通報演出で使う教師・小物はステージ内で先読みできる。
- エンディングCGは分岐決定後に対象1枚を読み込む。
- ローディング中や画像エラーでもゲーム状態を壊さない。読み込み失敗時は仮表示へ切り替える。
- 読み込み待ちの間にプレイ時間が減る設計を避け、既存のタイマー停止規則へ合わせる。
- 不要に1080×1920へ拡大保存せず、まず原寸を利用する。配信容量の圧縮が必要になった段階でWebPへ変換し、透過を維持する。
